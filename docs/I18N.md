# I18N status (M6.5 audit)

Hearth ships English-only, but §14 requires the codebase to be
**i18n-ready**: strings externalized so a second language is a data file,
not a code sweep.

## Infrastructure (in place)

- `src/i18n/en.ts` — typed dictionary (`en`) with dot-keys and
  `{placeholder}` interpolation; `t(key, vars?)` resolves it. Missing keys
  are compile errors (the key union is `keyof typeof en`).
- Adding a language = adding `src/i18n/<locale>.ts` with the same key shape
  and switching `t`'s dictionary source. No component changes needed.

## Migrated (as patterns)

- App shell: navigation rail labels, skip link (`AppShell.tsx`).
- The dictionary also pre-seeds composer/chat-header keys for the next sweep.

## Sweep recipe (per file)

1. Add keys to `en.ts` under a file-scoped prefix (`chat.`, `providers.`…).
2. Replace the literal with `t('key')`; interpolate values via
   `t('key', { name })` instead of template strings.
3. Plurals/interpolation beyond `{name}` substitution are intentionally not
   solved yet — revisit when a second locale is actually added.
